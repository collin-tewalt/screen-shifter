## Why

screen-shifter only runs from `cargo run`. To use it day to day, and to get it onto the Microsoft Store (and so onto winget through the Store's `msstore` source), it needs an identity: an icon, an MSIX package, start-with-Windows, and a version that the Store can update. Packaging also adds a new way for the app to be stopped (Windows closing it to update or uninstall the package), and the core promise that windows are never left hidden while the app isn't running has to survive that.

## What Changes

- **Icon** ("sheet breaks out", concept B): a monitor whose previous screen slides out past its left edge. Generated by a stdlib-only Python script (rectangles only, supersampled) into the MSIX logo PNGs and the tray icon sizes; a simplified version (no stand, no speed lines) for 16–24 px.
- **Tray icon** uses the new icon at the right size for the DPI instead of the generic application icon.
- **MSIX package**: `AppxManifest.xml` template (full trust, x64, Windows 10 2004+), a stdlib-only `tools/package.py` that builds release, stages exe + assets, fills the version from `Cargo.toml`, and runs `makeappx pack` (optionally `signtool` for sideload testing).
- **Start with Windows**: a startup task declared in the manifest, enabled by default; a **Start with Windows** checkbox in the tray menu reflects and toggles it (Windows' own Settings → Apps → Startup controls the same switch). Only in the packaged app; unpackaged dev builds show it disabled.
- **Closed by Windows for an update or uninstall**: handle `WM_CLOSE` like Exit and `WM_ENDSESSION` (exit cleanly after the existing `WM_QUERYENDSESSION` show-all), and `RegisterApplicationRestart` so Windows can relaunch the app after an update; the next launch takes the windows back either way. Verified by a spike on a sideloaded package before anything else is built on it.
- **Version**: `Cargo.toml` becomes the single source (0.5.0 → package `0.5.0.0`).
- Non-goals: Store listing and submission (separate `store-release` change), signing for distribution (the Store signs), an in-app updater (the Store updates), a winget-pkgs manifest, an exe icon resource for the unpackaged build.

## Capabilities

### New Capabilities
- `packaging`: icon, MSIX package and build, start with Windows, version source.

### Modified Capabilities
- `window-recovery`: packaged builds keep their own state file; the tray menu gains "Start with Windows"; windows are shown and the app exits cleanly when Windows closes it for an update or uninstall, and it relaunches after an update.

## Impact

- New: `tools/make_icons.py`, `tools/package.py`, `packaging/AppxManifest.xml`, `packaging/Assets/*.png` (generated, committed), `assets/tray-*.png` (generated, committed, `include_bytes!`).
- `main.rs`: tray icon from bytes, Start with Windows menu item, `WM_ENDSESSION`, `RegisterApplicationRestart`.
- `Cargo.toml`: version 0.5.0; `windows` features `ApplicationModel`, `Win32_System_Recovery` (restart registration), `Win32_Storage_Packaging_Appx` (package identity). No new crates.
- Manual one-time steps for the user: create the dev certificate (script provided) and trust it (admin), to sideload the test package.
- Packaged builds keep their state in `%LOCALAPPDATA%\screen-shifter-pkg` (separate from dev builds).
